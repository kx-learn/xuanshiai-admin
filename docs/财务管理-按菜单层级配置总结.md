## 二、各子页面配置/数据内容

### 1. 系统配置 `/finance-config`（配置域 `finance`）
后端已有的「财务配置」域（`admin_config_snapshot.namespace='finance'`），本页把以下 6 个**可控键**展成表格行（编号/配置名称/配置值/说明/更新时间），改动后 **800ms 防抖自动保存**，行内「保存」为手动立即落库：

| 配置名称 | 键（扁平） | 控件 | 说明 |
|---|---|---|---|
| 支付模式 | `payment_mode` | 下拉 mock/production | 支付渠道运行模式（正式商户密钥经密钥系统注入，域内不存明文） |
| 余额提现功能 | `withdrawal.enabled` | 开关 | 是否允许用户申请提现 |
| 最低提现金额 | `withdrawal.min_amount` | 数字（元） | 单笔提现最低金额 |
| 退款人工审核 | `refund.manual_review` | 开关 | 已支付订单退款是否需后台人工确认 |
| 自由收款 | `free_payment.enabled` | 开关 | 运营工具-自由收款开关 |
| 电子合同 | `e_contract.enabled` | 开关 | 电子合同功能开关（占位） |

- 读取：`GET /api/backend/admin/configs/finance`（前端经 lib `useConfigDomain`）
- 保存：`PATCH /api/backend/admin/configs/finance`（乐观锁 version + 审计 `admin_config_audit_log`）
- 只提交上述 6 键，`payment_channels/commission_rules` 等其余键由服务端快照保留

### 2. 收入明细 `/system-finance-order`
真实订单列表（`payment_order` 表），接入 `GET /api/backend/admin/finance/orders`：

- 列：订单号、会员 ID、商品、金额、状态（0 待支付/1 已支付/2 已关闭/3 已退款）、支付时间、创建时间
- 搜索：订单号 `order_no`、会员 ID `user_id`、状态 `status`、时间范围 `start_time ~ end_time`（本次后端补上时间过滤）
- 数据写入方：会员 VIP 下单、爆灯/置顶支付、红娘服务下单等（`payments/membership/matchmaker` service）

### 3. 积分明细（资金流水）`/system-credit-history`
账本流水（`account_ledger` 表），接入 `GET /api/backend/admin/finance/ledger`：

- 列：账户（类型/ID）、方向（CREDIT 收入绿/DEBIT 支出红）、金额、状态、来源类型、来源 ID、幂等键、时间
- 搜索：账户类型 `account_type`、账户 ID `account_id`、时间范围（后端已补）
- 流水来源：分成结算、分成释放、提现冻结、提现驳回回补、退款冲正等

### 4. 余额提现 `/system-cashout-history`
提现申请（`withdrawal_request` 表），接入 `GET /api/backend/admin/finance/withdrawals`：

- 列：账户、提现金额、收款账户（脱敏）、申请时间、状态、失败原因
- 顶部 Tab（全部/待审核/已完成/已驳回）本次**接通真实筛选**（`status` 参数），搜索支持账户 ID/状态/时间范围
- 审核动作为后端既有 `PATCH /admin/finance/withdrawals/{id}`（待审核→通过/驳回→处理中→成功/失败），状态流转由 `review_withdrawal` 校验

### 5. 统计报表 `/finance-statistic`
本次**后端新增**按日聚合接口 `GET /api/backend/admin/finance/daily-report`（依据 `payment_order.pay_time`）：

- 列：时间、成功付款笔数 `pay_count`、收入金额 `income_amount`、已退款 `refund_amount`
- 口径：`status=1`（已支付）计收入笔数与金额；`status=3`（已退款）计退款笔数与金额
- 搜索：时间范围 `start_date ~ end_date`（YYYY-MM-DD）
- 权限：需 `finance.read`

## 三、页面 ↔ 数据源/接口速查

| 页面 | 数据源类型 | 接口（后端 `/api/v1` 下） | 前端取数 |
|---|---|---|---|
| 系统配置 | 配置域 `finance` | `GET/PATCH /admin/configs/finance` | `useConfigDomain` + 防抖保存 |
| 收入明细 | 表 `payment_order` | `GET /admin/finance/orders` | ListPage endpoint |
| 资金流水 | 表 `account_ledger` | `GET /admin/finance/ledger` | ListPage endpoint |
| 余额提现 | 表 `withdrawal_request` | `GET /admin/finance/withdrawals`（+`PATCH` 审核） | ListPage endpoint + Tab 状态 |
| 统计报表 | 表 `payment_order` 聚合 | `GET /admin/finance/daily-report`（本次新增） | ListPage endpoint |

> 前端 ListPage 的统一解析：endpoint 前缀 `/api/backend/` 会被替换为后端 `/api/v1/`；带 `Authorization: Bearer` 令牌请求；返回 `{ items, total }` 或数组均支持。
