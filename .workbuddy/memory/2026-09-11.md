### `git revert` / `git apply` 在本仓库会连带删除无关文件（严重）

- 现象：任何一次会批量写入 `src/` 的 git 操作（`git revert`、`git apply --3way`）之后，
  **`src/` 下所有「不属于本次补丁」的跟踪文件会被从工作区删除**（实测 109~125 个），
  而 `src/` 之外（`docs/`、`api/`、`package.json` 等）的文件不受影响。
- 目录 mtime 与命令执行时刻完全吻合，`.git/index` 与 HEAD 始终同步（265 个文件），
  并非索引损坏；`git status` 不会把它算成暂存改动，所以**极易漏掉**。
- 恢复手段（可靠）：`git checkout -- <被删文件列表>`。
- 规避手段（推荐）：
  1. 先用 `git diff --name-only --diff-filter=A <commit>^ <commit>` 记下「本次应删除的文件」白名单；
  2. 执行撤销后，用 `comm -23 <本次删除列表> <白名单>` 得到误删集合，再 `git checkout --` 恢复；
  3. 真正需要撤销时优先用 `git apply --3way <反向补丁>`（`git diff <commit> <commit>^ > patch`），
     比 `git revert` 更好控制，但**同样要加白名单防护**。
- `git commit` 本身不会触发该问题。
- 另注意：该环境会偶发 SIGTERM 杀掉耗时较长/子进程较多的命令；避免在循环里反复调用 git
  （Windows 上每次 git 进程启动开销大），改用 `xargs` / 批量方式。
