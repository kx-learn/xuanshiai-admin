### 3) 排除的问题：路由遮蔽（实测无）

写脚本筛出 134 对「静态段 vs {参数} 同段数、方法重叠」的可疑组合，
再用**实测法**区分真伪：无 token 请求静态路径——
**401 = 命中正确路由（鉴权拦截）；422 = 被 `/{id}` 截获（路径参数 int 解析失败）**。

结论：项目的静态路由都注册在 `/{id}` 之前，顺序是有意维护的。
我原先那套「可疑对」静态筛选会把 `/admin/members/{member_id}/behavior` 与
`/admin/members/profile-ext/{user_id}` 判为冲突（理论 URL
`/admin/members/profile-ext/behavior` 同时匹配两者），但那是没人会请求的
URL，**实践中无害**，不要据此乱改路由顺序。

## 超级管理 Tab：接入两个写入接口（同日追加）

用户给了 `PATCH /admin/members/{member_id}/profile`（统一改会员信息）与
`PATCH /admin/members/{member_id}/match-quota`（改剩余牵线次数）两份文档，
要求「超级管理页使用这两个接口」。超级管理是**会员详情页的一个 Tab**
（`MemberDetailWorkspace.tsx` 的 `SuperTab`，key = `super`），原先整页是写死的 mock。

### 关键事实：接口字段 ≪ 页面字段

页面上 12 个控件里，只有 6 个能映射到这两个接口；**其余全是占位**：

| 页面控件 | 落库字段 | 能否预填当前值 |
|---|---|---|
| 实名认证 | `auth_status` | ✅ `MemberDetail.auth_status` |
| 姓名 | `real_name` | ✅ `RealnameReviewItem.real_name` |
| 实名信息（身份证号） | 无对应字段 | 只读展示 `id_card_masked` |
| 房产认证 | `house_verified` | ✅ `memberCertifications().house.status` |
| 学历认证 | `education_verified` | ✅ `memberCertifications().education.status` |
| 单身承诺 | `is_single_pledge`（布尔） | ❌ 无读取来源，留空 |
| 牵线剩余 | `available_count` | ✅ `memberMatchQuota()` |
| 账号绑定 / 置顶推荐 / 新人推荐 / 线上VIP / 线下VIP / 隐私设置 / 显示排序 / 推广红娘 / 牵线有效期 | **无对应字段** | 保留占位不动 |

用户明确选择：**无接口字段「保留占位不动」**。

### 认证状态枚举（易错）

`CERT_STATUS_OPTIONS = ["未认证", "待审核", "已认证", "认证失败"]`，
**数组下标即接口枚举值**（0 未提交 / 1 审核中 / 2 已通过 / 3 未通过）。
注意这与该页**原有 mock 的选项顺序**（未认证/已认证/待审核/认证失败）不同——
原顺序直接当索引用会错位，已统一为上面这个常量。

「单身承诺」原为 4 档 mock，因 `is_single_pledge` 是布尔，改成「否 / 是」两档。

### 「牵线剩余」的语义（重要）

接口是**直接设置**剩余次数（不是增减，后端文档特别强调）。
用户选择把 UI 从「增加 N 次」改为**「设为 N 次」**，提交 `available_count = 输入值`，
旁边显示「当前 X 次」作为参照；`reason` 必填。

### 实现要点

- 两个 PATCH **独立提交**（各自带必填 reason，各自的消息/错误态），不合并成一个按钮。
- 认证类字段走 **diff 提交**：维护 `initial` 快照（4 个字段的已加载原值），
  只把「界面值 ≠ 原值」的字段放进 payload；界面值为空 = 用户没动它。
  payload 只有 `reason` 时直接前端拦截（否则后端 422）。
- 校验前置：quota 需为 `0-1000000` 整数、reason 非空。
- `SuperTab` 改为自持拉取（`memberCertifications` + `memberMatchQuota` 并行），
  props 从 `data/loading/error` 换成 `memberId` / `profile` / `realnameReview`；
  父组件 `requests` 映射里删掉了冗余的 `super` 预取（`memberSuperInfo` 现已无调用方）。
- 新增前端封装 `updateMemberProfile` / `updateMemberMatchQuota` 与类型
  `MemberProfileUpdatePayload` / `MemberProfileUpdateResponse` /
  `MemberMatchQuotaUpdatePayload`（payload 类型均 `extends Record<string, unknown>`，
  以满足 `JsonBody` 赋值）。
